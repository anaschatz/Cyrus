# Qualified macOS inference bundle clone

`inference/scripts/clone_qualified_macos_bundle.py` is an offline maintenance
tool, not part of the `jarvis_inference` wheel. It creates a new private clone
of one stopped macOS inference bundle and never edits the source.

The source must be fully stopped and the destination must not exist. Use a
trusted maintenance Python with this repository's `inference/src` on its
module path:

```zsh
PYTHONPATH=inference/src .venv/bin/python \
  inference/scripts/clone_qualified_macos_bundle.py \
  --source /absolute/path/to/stopped-qualified-bundle \
  --destination /absolute/path/to/new-clean-bundle \
  --manifest-relative manifest-qwen3-4b-capable.json
```

The tool scans and hashes the complete source before creating the destination.
It rejects links, reparse points, special files, an existing or overlapping
destination, manifest/artifact drift, invalid wheels, invalid or incomplete
installed-distribution `RECORD` files, qualification/runtime identity drift,
and any unknown unrecorded file below `site-packages`. During the copy it
rehashes every file, writes only owner-private files and directories, and then
revalidates the complete destination. Failure removes only the destination
directory created by that invocation; failure to prove safe rollback is itself
reported as `bundle_rollback_incomplete`.

The clone omits unrecorded `.DS_Store` files and strict numeric conflict-copy
names such as `module 2.py`, `METADATA 2`, or a space-suffixed duplicate
directory. It also omits proven generated bytecode only within the
manifest-declared `site-packages`: an exact CPython 3.11 PEP 3147
`__pycache__` name, optionally with a numeric `opt-N` suffix, must resolve to
its deterministic sibling `.py`. That source must be included, owned by a
validated installed `RECORD`, and byte-identical to the corresponding member
of every owning manifest-pinned wheel. The `.pyc` itself must be unrecorded
and absent from every bundle identity document. Sourceless, malformed,
wrong-tag, recorded, referenced, linked, or source/wheel-mismatched caches
fail closed. The cloned `site-packages` contains no `.pyc` file or
`__pycache__` directory; caches outside `site-packages`, including the sealed
standard library, remain ordinary full-bundle data.

The tool also omits exactly nine standard
CPython 3.11 convenience symlinks (`python`, `python3`, `2to3`, `idle3`,
`pydoc3`, `python3-config`, two `pkgconfig` aliases and the `python3.1` manpage
alias). Each link must have its exact known relative basename target, resolve
to a regular file inside the same bundle, and be absent from the manifest,
qualification report, fixture identity and every installed `RECORD`. The
target file is copied normally. Absolute, escaping, dangling, chained,
recorded, identity-bound or differently named links fail closed; the tool
never dereferences a link into the destination. A matching file named by a manifest,
qualification report, fixture identity, or installed `RECORD` is preserved,
not silently deleted. All other ordinary files outside `site-packages` are
copied so the clone remains a full bundle rather than a hand-picked runtime
subset. The JSON result is content-free: fixed codes, counts, byte totals and
digests only; it emits no paths, package names, prompts, model content or
credentials.

Duplicate `RECORD` ownership also fails closed, with one version-pinned
exception for the audited MLX 0.32.0 wheel pair. `mlx` and `mlx-metal` may
jointly own exactly the five audited members under `mlx`: `__main__.py`,
`_reprlib_fix.py`, `extension.py`, `py.typed`, and `utils.py`. No other shared
path is accepted, and all five overlaps must be present. For each one, both
installed `RECORD` rows must contain the same explicit SHA-256 and size, the
installed file must match them, both manifest-pinned wheels must contain that
exact member, and both wheel-member bytes must have the same identity. A
different version, owner pair, path set, missing member, blank size, or byte
mismatch is rejected. This exception is not a general-purpose
namespace-package allowance; an MLX upgrade requires a new audit and policy
change.

The frozen qualification report and manifest may refer to the qualified
gateway wheel through different safe relative paths. Both artifacts are
preserved and validated independently. Their basenames, declared SHA-256 and
size must be identical, both files must remain in the included clone, and a
streaming byte comparison must succeed. Path equality alone is deliberately
not required, and neither identity document is rewritten. A missing, unsafe,
excluded, renamed, resized, rehashed, or byte-different alias fails closed.

## Qualification decision

A successful clone preserves the frozen manifest and qualification report
byte-for-byte. They remain valid because every artifact, installed `RECORD`
file, gateway package digest, gateway wheel, fixture runner and canonical
runtime identity is unchanged; absolute bundle paths are not part of that
identity. No requalification is required solely to remove contamination or
generated cache data that was unrecorded and outside the qualified gateway
digest.

The tool deliberately refuses a cleanup that would change qualified identity.
In particular, removing a file listed by `RECORD`, a declared artifact, or a
Python file already included in the persisted gateway package digest requires
a clean environment rebuild/reinstall, a newly generated manifest, and a new
native qualification. A recorded conflict copy therefore remains in a
successful clone; this command must not be used to make a dirty recorded wheel
look clean.
